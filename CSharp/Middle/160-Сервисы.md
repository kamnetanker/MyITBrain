# Фоновые задачи

Фоновая задача - это код, который исполняется независимо от пользовательских запросов и не блокирует основной поток приложения.

Типичные сценарии:

- Периодическая очистка устаревших данных (логи, сессии, кеш)
- Отправка уведомлений
- Обработка очередей (тяжелые фоновые операции)
- Мониторинг и сбор метрик
- Синхронизации с внешними системами

Ключевые требования:

- Graceful shutdown - при остановке приложения, фоновая задача должна корректно завершится.
- Устойчивость - ошибка в фоновой задаче не должна приводить к останову всего приложения.
- Управляемость - должна быть возможность запускать и останавливать фоновые задачи.

В .Net для фоновых задач есть 2 основных пути реализации:

- **Встроенный механизм** `IHostedService` / `BackgroundService` - для простых задач, работающих внутри хоста.
- **Расширенные библиотеки** `Hangfire` / `Quartz.NET` - для сложных сценариев с планированием, персистентностью и дашбордом

## IHostedService

`IHostedService` - интерфейс из пространства имён `Microsoft.Extensions.Hosting`, который определяет методы для управления жизненным циклом фоновой задачи. Классы, реализующие этот интерфейс могут быть использованы как фоновые задачи.

```c#
// Контракт фоновой задачи
public interface IHostedService
{
    // Вызывается при запуске хоста
    Task StartAsync(CancellationToken cancellationToken);
    
    // Вызывается при graceful shutdown
    Task StopAsync(CancellationToken cancellationToken);
}
```

Используется, когда требуется полный контроль над фоновой задачей и порядком её исполнения, фоновая задача не содержит бесконечных циклов и нужно выполнить синхронный код во время старта.

Пример реализации классом интерфейса `IHostedService`:

```c#
public class SimpleHostedService : IHostedService
{
    private readonly ILogger<SimpleHostedService> _logger;

    public SimpleHostedService(ILogger<SimpleHostedService> logger)
    {
        _logger = logger;
    }

    // Выполняется при старте приложения
    public Task StartAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("Сервис запущен");
        return Task.CompletedTask;
    }

    // Выполняется при остановке приложения
    public Task StopAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("Сервис остановлен");
        return Task.CompletedTask;
    }
}
```

## BackgroundService

`BackgroundService` - абстрактный класс, реализующий `IHostedService`. Он уже содержит реализацию `StartAsync` и `StopAsync` и для классов-наследников, реализующих данный абстрактный класс необходимо лишь переопределить метод `ExecuteAsync`, остальную работу выполняет `BackgroundService`.

```c#
// Контракт абстрактного класса для фоновых задач
public abstract class BackgroundService : IHostedService, IDisposable
{
    // Абстрактный метод — его нужно переопределить
    protected abstract Task ExecuteAsync(CancellationToken stoppingToken);
    
    // Реализация IHostedService (уже готова)
    public virtual Task StartAsync(CancellationToken cancellationToken) { ... }
    public virtual Task StopAsync(CancellationToken cancellationToken) { ... }
}
```

Ключевое отличие заключается в том, что `BackgroundService` пригоден для создания бесконечного цикла, требуется лишь реализовать `ExecuteAsync`, остальные методы уже реализованы. 

```c#
// Пример класса, реализующего BackgroundService.
public class MyBackgroundService : BackgroundService
{
    private readonly ILogger<MyBackgroundService> _logger;

    public MyBackgroundService(ILogger<MyBackgroundService> logger)
    {
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        // Бесконечный цикл, пока приложение работает
        while (!stoppingToken.IsCancellationRequested)
        {
            // Твоя работа
            _logger.LogInformation("Фоновая задача выполняется...");
            
            // Ожидание с учётом токена отмены
            await Task.Delay(TimeSpan.FromSeconds(10), stoppingToken);
        }
    }
}
```

**Важно** начиная с .Net 10 весь код `ExecuteAsync` выполняется асинхронно, а не как было раньше - до первого await было синхронное исполнение. Весь код, который следует выполнить синхронно теперь нужно размещать в конструкторе или реализовывать `IHostedService` вручную.

Есть так же вариант реализации `IHostedLifecycleService`, позволяющий точно контроллировать порядок работы фонового приложения.

Контракт:

```c#
public interface IHostedLifecycleService : IHostedService
{
    // Вызывается ДО StartAsync
    Task StartingAsync(CancellationToken cancellationToken);
    
    // Вызывается ПОСЛЕ StartAsync
    Task StartedAsync(CancellationToken cancellationToken);
    
    // Вызывается ДО StopAsync
    Task StoppingAsync(CancellationToken cancellationToken);
    
    // Вызывается ПОСЛЕ StopAsync
    Task StoppedAsync(CancellationToken cancellationToken);
}
```

Порядок выполнения  

Хост вызывает методы в строгой последовательности:  

- StartingAsync() для всех зарегистрированных сервисов.
- StartAsync() для всех зарегистрированных сервисов (унаследован от IHostedService).
- StartedAsync() для всех зарегистрированных сервисов.
- (Приложение работает)
- StoppingAsync() для всех зарегистрированных сервисов.
- StopAsync() для всех зарегистрированных сервисов (унаследован от IHostedService).
- StoppedAsync() для всех зарегистрированных сервисов.

Пример с контролем асинхронной и синхронной части исполнения:

```c#
public class LifecycleDemoService : IHostedLifecycleService
{
    private readonly ILogger<LifecycleDemoService> _logger;

    public LifecycleDemoService(ILogger<LifecycleDemoService> logger)
    {
        _logger = logger;
    }

    // 1. Вызывается ПЕРЕД StartAsync
    public async Task StartingAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("1. StartingAsync: Выполняется ДО запуска службы.");

        // Асинхронная инициализация (например, применение миграций, загрузка кэша)
        await Task.Delay(100, cancellationToken); // Имитация асинхронной работы

        // Синхронный код
        _logger.LogInformation("1. StartingAsync: Асинхронная инициализация завершена.");
    }

    // 2. Вызывается как часть IHostedService.StartAsync
    public Task StartAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("2. StartAsync: Запуск основной логики службы.");

        // Здесь обычно запускают фоновый цикл, но для примера просто логируем
        // Синхронный код
        return Task.CompletedTask;
    }

    // 3. Вызывается ПОСЛЕ StartAsync
    public Task StartedAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("3. StartedAsync: Служба успешно запущена.");

        // Синхронный код, например, подписка на события
        return Task.CompletedTask;
    }

    // 4. Вызывается ПЕРЕД StopAsync
    public Task StoppingAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("4. StoppingAsync: Выполняется ДО остановки службы.");

        // Синхронный код, например, отписка от событий
        return Task.CompletedTask;
    }

    // 5. Вызывается как часть IHostedService.StopAsync
    public Task StopAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("5. StopAsync: Остановка основной логики службы.");

        // Здесь обычно останавливают фоновый цикл, но для примера просто логируем
        // Синхронный код
        return Task.CompletedTask;
    }

    // 6. Вызывается ПОСЛЕ StopAsync
    public async Task StoppedAsync(CancellationToken cancellationToken)
    {
        _logger.LogInformation("6. StoppedAsync: Служба полностью остановлена.");

        // Асинхронная очистка ресурсов
        await Task.Delay(50, cancellationToken); // Имитация асинхронной очистки

        // Синхронный код, например, запись финального состояния в лог
        _logger.LogInformation("6. StoppedAsync: Асинхронная очистка завершена.");
    }
}
```

Регистрация в DI:

```c#
var builder = Host.CreateApplicationBuilder(args);

// Регистрация службы с полным жизненным циклом
builder.Services.AddHostedService<LifecycleDemoService>();

var host = builder.Build();
await host.RunAsync();
```

## Примеры Встроенных механизмов

**ASP.NET**

Сценарий: Веб-приложение требует периодической очистки таблицы сессий от записей старше 7 дней.



```c#
public class SessionCleanupService : BackgroundService
{
    private readonly ILogger<SessionCleanupService> _logger;
    private readonly IServiceProvider _serviceProvider;
    private readonly TimeSpan _checkInterval = TimeSpan.FromHours(1);

    public SessionCleanupService(
        ILogger<SessionCleanupService> logger,
        IServiceProvider serviceProvider)
    {
        _logger = logger;
        _serviceProvider = serviceProvider;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        _logger.LogInformation("SessionCleanupService запущен");

        using var timer = new PeriodicTimer(_checkInterval);

        while (await timer.WaitForNextTickAsync(stoppingToken))
        {
            try
            {
                /*
                В BackgroundService мы не можем просто взять и использовать AppDbContext напрямую, потому что:

                BackgroundService регистрируется как Singleton (живёт всё время работы приложения).

                AppDbContext регистрируется как Scoped (живёт один запрос).

                Если бы мы внедрили AppDbContext напрямую в синглтон-сервис, он бы тоже стал жить вечно — это привело бы к утечкам памяти, кэшированию старых данных и проблемам с производительностью.

                Решение: мы создаём область (Scope) вручную — это как искусственный «запрос». Внутри этой области все Scoped-сервисы (включая DbContext) живут ровно столько, сколько существует область. Когда область завершается (using-блок закрывается), все её сервисы корректно уничтожаются.

                Что такое IServiceProvider?

                IServiceProvider — это главный DI-контейнер приложения. Он доступен везде и создаётся автоматически при старте приложения. Его не нужно регистрировать отдельно — он всегда есть, и его можно запросить через конструктор. В примере ниже мы внедряем IServiceScopeFactory — фабрику для создания областей, через которую получаем доступ к DI-контейнеру внутри фоновой задачи.
                */

                // Создаём область для создания Scoped-сервисов, когда область в которой создан scope кончится - все связные сервисы освободят ресурсы. 
                using var scope = _serviceProvider.CreateScope();
                var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();

                var cutoffDate = DateTime.UtcNow.AddDays(-7);
                var oldSessions = await dbContext.Sessions
                    .Where(s => s.LastActivity < cutoffDate)
                    .ToListAsync(stoppingToken);

                if (oldSessions.Any())
                {
                    dbContext.Sessions.RemoveRange(oldSessions);
                    await dbContext.SaveChangesAsync(stoppingToken);
                    _logger.LogInformation("Удалено {Count} устаревших сессий", oldSessions.Count);
                }
            }
            catch (OperationCanceledException)
            {
                // Ожидаемая остановка
                break;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Ошибка при очистке сессий");
            }
        }

        _logger.LogInformation("SessionCleanupService остановлен");
    }
}
```

Регистрация в DI:

```c#
// Program.cs

```

**Классическое приложение**

Сценарий: Консольная утилита, которая мониторит папку на наличие новых файлов и логирует изменения.

```c#
public class FolderMonitorService : BackgroundService
{
    private readonly ILogger<FolderMonitorService> _logger;
    private readonly string _folderPath;
    private readonly TimeSpan _checkInterval = TimeSpan.FromSeconds(30);

    public FolderMonitorService(ILogger<FolderMonitorService> logger)
    {
        _logger = logger;
        _folderPath = Path.Combine(AppContext.BaseDirectory, "incoming");
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        // Создаём папку, если её нет
        Directory.CreateDirectory(_folderPath);
        _logger.LogInformation("FolderMonitorService запущен. Папка: {FolderPath}", _folderPath);

        // Храним хэш-набор известных файлов
        var knownFiles = new HashSet<string>();

        using var timer = new PeriodicTimer(_checkInterval);

        while (await timer.WaitForNextTickAsync(stoppingToken))
        {
            try
            {
                var currentFiles = Directory.GetFiles(_folderPath)
                    .Select(Path.GetFileName)
                    .ToHashSet();

                // Новые файлы
                var newFiles = currentFiles.Except(knownFiles).ToList();
                foreach (var file in newFiles)
                {
                    _logger.LogInformation("Обнаружен новый файл: {FileName}", file);
                }

                // Удалённые файлы
                var removedFiles = knownFiles.Except(currentFiles).ToList();
                foreach (var file in removedFiles)
                {
                    _logger.LogInformation("Файл удалён: {FileName}", file);
                }

                knownFiles = currentFiles;
            }
            catch (OperationCanceledException)
            {
                break;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Ошибка при мониторинге папки");
            }
        }

        _logger.LogInformation("FolderMonitorService остановлен");
    }
}
```

Регистрация в консольном приложении:

```c#
// Program.cs
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

var host = Host.CreateDefaultBuilder(args)
    .ConfigureServices((context, services) =>
    {
        services.AddHostedService<FolderMonitorService>();
        services.AddLogging();
    })
    .Build();

await host.RunAsync();
```

## Hangfire

Hangfire - библиотека с открытым исходным кодом для выполнения фоновых задач в .Net приложениях без необходимости писать отдельные Windows-службы или консольные приложения.

Ключевые возможности:

- Fire-and-Forget - задачи,выполняемые одир раз сразу после создания
- Delayed Jobs - задачи, которые необходимо выполнить через некоторое время
- Recurring Jobs - CRON задачи в рамках приложения, т.е. по расписанию
- Continuations - задачи, выполняемые после завершения основного приложения.

Преимущества Hangfire:

- Персистентность - задача хранится в базе данных и переживает перезапуск приложения.
- Встроенный дашборд, показывающий задачи и позволяющий их мониторить
- Надёжность - задачи автоматически перезапускаются после ошибок
- Распределённость - задачи можно делегировать на другие машины
- Расширяемость - фильтры задач аналогичны MVC фильтрам

Использовать Hangfire имеет смысл, когда нужно сложное поведение для сервисов, очень хочется дашборд для задач, нужна обработка очередей с приоритетами и требуется выполнения задач на нескольких серверах.

**Установка и настройка**

```bash
# Основной пакет и хранилище (SQL Server)
dotnet add package Hangfire.Core
dotnet add package Hangfire.SqlServer

# Для ASP.NET Core интеграции
dotnet add package Hangfire.AspNetCore
```

Настройка в ASP.NET Core

```C#
// Program.cs
using Hangfire;
using Hangfire.SqlServer;

var builder = WebApplication.CreateBuilder(args);

// 1. Регистрация Hangfire
builder.Services.AddHangfire(config =>
    config.UseSqlServerStorage(builder.Configuration.GetConnectionString("HangfireConnection")));

// 2. Регистрация сервера Hangfire
builder.Services.AddHangfireServer();

// 3. Добавление дашборда
var app = builder.Build();

app.UseHangfireDashboard(); // доступен по /hangfire

app.MapControllers();
app.Run();
```

Настройка в классическом приложении:

```c#
// Program.cs
using Hangfire;
using Hangfire.SqlServer;

GlobalConfiguration.Configuration
    .UseSqlServerStorage(@"Server=.\SQLEXPRESS; Database=Hangfire.Sample; Integrated Security=True");

using (var server = new BackgroundJobServer())
{
    Console.WriteLine("Hangfire Server запущен. Нажмите Enter для выхода.");
    Console.ReadLine();
}
```

**Базовые операции**

```c#
//Fire-and-forget
// В контроллере ASP.NET Core
public class JobsController : ControllerBase
{
    [HttpPost]
    public IActionResult CreateJob()
    {
        var jobId = BackgroundJob.Enqueue(() => Console.WriteLine("Fire-and-forget!"));
        return Ok(new { JobId = jobId });
    }
}

//Delayed Job (отложенная задача)
// В консольном приложении
var jobId = BackgroundJob.Schedule(
    () => Console.WriteLine("Delayed!"),
    TimeSpan.FromMinutes(5));

// Recurring Job (повторяющаяся задача)
// В методе Configure или при старте приложения
RecurringJob.AddOrUpdate(
    "myrecurringjob",               // уникальный идентификатор
    () => Console.WriteLine("Recurring!"),
    Cron.Daily);                    // каждый день в полночь
```

Hangfire имеет интеграцию с DI:

```c#
// Регистрация сервиса, который будет использоваться в задаче
builder.Services.AddScoped<IEmailService, EmailService>();

// Создание повторяющейся задачи с DI
RecurringJob.AddOrUpdate<IEmailService>(
    "daily-summary",
    service => service.SendDailySummaryAsync(),
    Cron.Daily);
```

**Важно**: Hangfire создаёт отдельную область (scope) для каждой задачи, поэтому Scoped-сервисы работают корректно.

Использование `IBackgroundJobClient` через `DI` (**рекомендуемый подход**):

```c#
    public IActionResult CreateJob()
    {
        var jobId = _jobClient.Enqueue(() => Console.WriteLine("Job!"));
        return Ok(new { JobId = jobId });
    }
}
```

## Примеры

**ASP.NET**

Сценарий: Веб-приложение должно отправлять ежедневную рассылку с отчётом о продажах.

```c#
// EmailService.cs
public interface IEmailService
{
    Task SendDailyReportAsync();
}

public class EmailService : IEmailService
{
    private readonly ILogger<EmailService> _logger;
    private readonly AppDbContext _dbContext;

    public EmailService(ILogger<EmailService> logger, AppDbContext dbContext)
    {
        _logger = logger;
        _dbContext = dbContext;
    }

    public async Task SendDailyReportAsync()
    {
        _logger.LogInformation("Начало отправки ежедневного отчёта");
        
        // Получение данных для отчёта
        var sales = await _dbContext.Orders
            .Where(o => o.CreatedAt >= DateTime.UtcNow.Date)
            .ToListAsync();

        // Отправка email (имитация)
        await Task.Delay(1000);
        
        _logger.LogInformation("Ежедневный отчёт отправлен. Заказов: {Count}", sales.Count);
    }
}
```

Настройка **Hangfire**:

```c#
// Program.cs
builder.Services.AddScoped<IEmailService, EmailService>();

var app = builder.Build();

// Регистрация повторяющейся задачи сразу после настройки

    "daily-report",
    service => service.SendDailyReportAsync(),
    Cron.Daily(9, 0)); // каждый день в 9:00

app.UseHangfireDashboard(); // /hangfire

app.Run();
```

**Классическое приложение**

Сценарий: Консольное приложение, которое выполняет резервное копирование базы данных каждый час.

```c#
// BackupService.cs
public interface IBackupService
{
    Task PerformBackupAsync();
}

public class BackupService : IBackupService
{
    private readonly ILogger<BackupService> _logger;
    private readonly string _backupPath;

    public BackupService(ILogger<BackupService> logger)
    {
        _logger = logger;
        _backupPath = Path.Combine(AppContext.BaseDirectory, "backups");
    }

    public async Task PerformBackupAsync()
    {
        Directory.CreateDirectory(_backupPath);
        
        var timestamp = DateTime.Now.ToString("yyyy-MM-dd-HH-mm");
        var backupFile = Path.Combine(_backupPath, $"db-backup-{timestamp}.bak");
        
        _logger.LogInformation("Начало резервного копирования в {BackupFile}", backupFile);
        
        // Имитация резервного копирования
        await Task.Delay(2000);
        
        _logger.LogInformation("Резервное копирование завершено");
    }
}
```

Настройка Hangfire в консольном приложении

```c#
// Program.cs
using Hangfire;
using Hangfire.SqlServer;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

var host = Host.CreateDefaultBuilder(args)
    .ConfigureServices((context, services) =>
    {
        services.AddScoped<IBackupService, BackupService>();
        services.AddHangfire(config =>
            config.UseSqlServerStorage("Server=localhost;Database=Hangfire;Integrated Security=True"));
        services.AddHangfireServer();
    })
    .Build();

// Регистрация повторяющейся задачи
RecurringJob.AddOrUpdate<IBackupService>(
    "hourly-backup",
    service => service.PerformBackupAsync(),
    Cron.Hourly);

await host.RunAsync();
```
