# Кеширование: InMemoryCache, IDistributedCache и Redis

## Кеширование

`Кеширование` - сохранение данных в быстром хранилище (обычно в оперативной памяти) для ускорения повторных обращений, основная цель - уменьшение времени ответа и снижение нагрузки на внешние системы.

**Когда использовать?**

- Данные часто спрашивают, но они редко меняются
- Данные дорого получать (сложные SQL запросы, удалённые сервера, внешние API)
- Допустима задержка в актуальности данных

**Когда не использовать?**

- Данные часто меняются (транзакции, счётчики, мониторы показателей)
- Важны самые свежие данные

**Формы кеширования**

- В памяти (In-Memory) - данные хранятся в памяти текущего процесса, самый быстрый кеш, но теряется при перезапуске приложения, если не создан RAM-диск с хранением в файле в RAM-диск
- В файловой системе (In-File) - в файловой системе на быстром хранилище (ssd) создаётся файл для хранения кеша
- Распределённый (Distributed) - данные хранятся во внешнем хранилище (Redis, SQL Server), доступ из разных экземпляров приложения. Используется, когда источник данных достаточно удалён, чтобы в локальной сети имело смысл иметь кеш-хранилище.

## In-Memory: IMemoryCache - встроенный кеш в памяти

`IMemoryCache` - интерфейс для работы с кешем в памяти, встроенный в .Net

**Методы:**

- `Set<T>(key, value, options)` - Добавляет ключ и данные в хранилище
- `TryGetValue<T>(key, out value)` - Пытается получить значение по ключу из хранилища, возвращает true если успешно
- `Get<T>(key)` - Получает значение из хранилища или null
- `Remove(key)` - Удаляет запись из кеш-хранилища.

**Использование:**

```c#
// В Program.cs
// Добавляем MemoryCache в DI-контейнер
builder.Services.AddMemoryCache();

// В ProductsController.cs - для примера
// Внедрение через DI контейнер
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    private readonly IMemoryCache _cache;

    // Внедрение IMemoryCache через конструктор
    public ProductsController(IMemoryCache cache)
    {
        _cache = cache;
    }
}

// Добавление данных в кеш
// Простая запись без дополнительных параметров
_cache.Set("Product_123", productData);

// Запись с использованием ключа и значения
_cache.Set("Product_123", productData, TimeSpan.FromMinutes(5));


// Получение данных из кеша
// Способ 1: TryGetValue (рекомендуемый)
if (_cache.TryGetValue<ProductData>("Product_123", out var product))
{
    // Данные есть в кэше
    return Ok(product);
}

// Способ 2: Get (возвращает null, если ключа нет)
var product = _cache.Get<ProductData>("Product_123");
if (product != null)
{
    // Данные есть
}

// Удаление данных из кеша
_cache.Remove("Product_123");


// Get-or-Set pattern 
// Часто нужно: если данные есть в кэше — вернуть их, иначе загрузить, сохранить в кэш и вернуть.
// Использование GetOrCreate (асинхронная версия — GetOrCreateAsync)
var product = await _cache.GetOrCreateAsync("Product_123", async entry =>
{
    // Этот код выполняется только при промахе кэша
    var data = await _productService.GetFromDatabaseAsync(123);
    
    // Устанавливаем время жизни записи (опционально)
    entry.SetAbsoluteExpiration(TimeSpan.FromMinutes(10));
    
    return data;
});
```

**Политики вытеснения**

Политики определяют когда значение вытесняется(удаляется) из кеша

```c#
// AbsoluteExpiration
// Запись удаляется ровно через заданное время, независимо от того, обращались ли к ней.
_cache.Set("Product_123", product, new MemoryCacheEntryOptions
{
    AbsoluteExpiration = DateTimeOffset.Now.AddMinutes(10)
});

// SlidingExpiration
// Запись удаляется, если к ней не обращались в течение заданного времени. Каждое обращение «сбрасывает» таймер.
_cache.Set("Product_123", product, new MemoryCacheEntryOptions
{
    SlidingExpiration = TimeSpan.FromMinutes(2)
});
// Если к записи не обращались 2 минуты — она удалится.

// Absolute + Sliding
// Если истекло абсолютное время ИЛИ к записи не обращались указанное время то удалить запись
_cache.Set("Product_123", product, new MemoryCacheEntryOptions
{
    AbsoluteExpiration = DateTimeOffset.Now.AddHours(1), // максимум 1 час
    SlidingExpiration = TimeSpan.FromMinutes(5)          // если не трогать 5 минут — удалится
});

// Priority
// Позволяет управлять тем, какие записи вытесняются при исчерпании свободного места
// High данные удаляются в последнюю очередь
var options = new MemoryCacheEntryOptions
{
    Priority = CacheItemPriority.High
};
_cache.Set("CriticalData", data, options);
```

**MemoryCacheEntryOptions для гибкой настройки**

```c#
var options = new MemoryCacheEntryOptions()
    .SetAbsoluteExpiration(TimeSpan.FromMinutes(10)) // Удалять записи каждые 10 минут
    .SetSlidingExpiration(TimeSpan.FromMinutes(2)) // Или если их не трогали 2 минуты
    .SetPriority(CacheItemPriority.High) // Приоритет данных высокий
    .RegisterPostEvictionCallback((key, value, reason, state) => // Когда данные удаляются вызываем делегат
    {
        // Колбэк, вызываемый при удалении записи из кэша
        Console.WriteLine($"Ключ {key} удалён. Причина: {reason}");
        // Expired - истекло время жизни
        // Removed - принудительно вызван Remove
        // Replaced - запись перезаписана
        // Capacity - размер кеша привышен и запись вытеснена
    });

_cache.Set("User_42", userData, options);
```

**Тестирование кеша**

```c#
// Для тестов используется реальный IMemoryCache, который создаётся через DI
// Пример с реальным кешем
[Fact]
public void Cache_ShouldStoreAndRetrieveValue()
{
    // Arrange
    var cache = new MemoryCache(new MemoryCacheOptions());
    var key = "testKey";
    var expected = "testValue";

    // Act
    cache.Set(key, expected);
    var actual = cache.Get<string>(key);

    // Assert
    Assert.Equal(expected, actual);
}
// Пример с заглушкой
[Fact]
public void GetProduct_CacheHit_ReturnsCachedValue()
{
    // Arrange
    var mockCache = new Mock<IMemoryCache>();
    var product = new Product { Id = 1, Name = "Test" };
    object cachedProduct = product;

    mockCache.Setup(x => x.TryGetValue(It.IsAny<object>(), out cachedProduct))
             .Returns(true);

    var service = new ProductService(mockCache.Object);

    // Act
    var result = service.GetProduct(1);

    // Assert
    Assert.Equal(product, result);
}
```

## DistributedCache - распределённый кеш

`Распределённый кеш` (`DistributedCache`) - кеш, который разделяется на несколько экземпляров приложения, что полезно для кластерной обработки данных или для микросервисов. Обычно работает на базе внешнего сервиса, вроде Redis или SQL Server, к которому все экземпляры приложения и обращаются.

## Установка, настройка и использование

Первым делом создадим внешний сервис кеша через Docker контейнер

```bash
# --name my-redis — имя контейнера.
# -p 6379:6379 — проброс порта (локальный → контейнер).
# -d redis — запуск в фоновом режиме с образом Redis
docker run --name my-redis -p 6379:6379 -d redis
# Проверка, что всё запустилось и работает
docker ps
# Должен отображаться контейнер my-redis со статусом Up.
# Остановка и удаление контейнера:
docker stop my-redis
docker rm my-redis
```

Далее установка пакета для интеграции с Redis: `dotnet add package Microsoft.Extensions.Caching.StackExchangeRedis`

```c#
// Регистрация в Program.cs
var builder = WebApplication.CreateBuilder(args);

// Регистрируем распределённый кэш с Redis
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "localhost:6379"; // адрес Redis
    options.InstanceName = "MyApp_";          // префикс для ключей (опционально)
});

builder.Services.AddControllers();
var app = builder.Build();
app.Run();
```

Так же добавим строку подключения в `appsettings.json`

```json
{
  "Redis": {
    "ConnectionString": "localhost:6379,password=yourpass,defaultDatabase=0"
  }
}
```

И изменим подключение через конфигурационную строку:

```c#
var connectionString = builder.Configuration.GetConnectionString("Redis:ConnectionString");
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = connectionString;
});
```

Пример использования в контроллере:

```c#
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    private readonly IDistributedCache _cache;

    // Внедрение IDistributedCache через конструктор
    public ProductsController(IDistributedCache cache)
    {
        _cache = cache;
    }

    [HttpGet("{id}")]
    public async Task<IActionResult> GetProduct(int id)
    {
        var cacheKey = $"Product_{id}";

        // 1. Пытаемся получить данные из кэша
        var cachedData = await _cache.GetAsync(cacheKey);
        if (cachedData != null)
        {
            // Данные есть — десериализуем и возвращаем
            var product = JsonSerializer.Deserialize<Product>(cachedData);
            return Ok(product);
        }

        // 2. Данных в кэше нет — загружаем из БД
        var productFromDb = await _productService.GetByIdAsync(id);

        // 3. Сохраняем в кэш (сериализуем в JSON)
        var serialized = JsonSerializer.SerializeToUtf8Bytes(productFromDb);
        var options = new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
        };
        await _cache.SetAsync(cacheKey, serialized, options);

        return Ok(productFromDb);
    }

    [HttpDelete("{id}")]
    public async Task<IActionResult> DeleteProduct(int id)
    {
        var cacheKey = $"Product_{id}";
        await _cache.RemoveAsync(cacheKey);
        return NoContent();
    }
}
// Важно: IDistributedCache работает с byte[], поэтому перед сохранением объекты нужно сериализовать (например, в JSON)
```

**Рекомендация: используй `JsonSerializer.SerializeToUtf8Bytes()` и `JsonSerializer.Deserialize<T>()` — они работают напрямую с `byte[]` без лишних преобразований.**

**Политики истечения срока действия**

```c#
//Абсолютное истечение
var options = new DistributedCacheEntryOptions
{
    AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
};
await _cache.SetAsync(key, data, options);
// Запись будет удалена ровно через 10 минут

// Скользящее истечение
var options = new DistributedCacheEntryOptions
{
    SlidingExpiration = TimeSpan.FromMinutes(2)
};
await _cache.SetAsync(key, data, options);
// Если к записи не обращались 2 минуты — она удалится

// Комбинация (Absolute + Sliding)
var options = new DistributedCacheEntryOptions
{
    AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(1),
    SlidingExpiration = TimeSpan.FromMinutes(5)
};
await _cache.SetAsync(key, data, options);
// Удалится, когда наступит абсолютное время ИЛИ если не обращались 5 минут
```

Важно: в отличие от `IMemoryCache`, `IDistributedCache` не гарантирует автоматическое обновление `SlidingExpiration` при каждом чтении. Для обновления нужно вызывать `RefreshAsync(key)` или `GetAsync`/`SetAsync`. Однако в большинстве реализаций (включая `Redis`) `GetAsync` автоматически обновляет скользящее время.

**Продакшн**

Для продакшена рекомендуется использовать `Redis` — он обеспечивает наилучшую производительность.

```c#
// Настройка для Azure Cache for Redis
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "your-azure-redis.redis.cache.windows.net:6380,password=yourkey,ssl=True,abortConnect=False";
    options.InstanceName = "MyApp_";
});
```
